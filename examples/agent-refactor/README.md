# Agent Refactor Example

A worked walkthrough of the smokepod guardrail loop: lock a CLI's behavior with
a characterization baseline, apply a scripted "bad refactor" that **passes unit
tests**, and watch `verify` catch the exact output change that the tests could
not see. Then review the change through `smokepod update` instead of discovering
it in production.

The limit this example demonstrates: smokepod checks **parity, not
correctness**. The baseline does not know which greeting is "right"; it makes
any behavior change visible and reviewable. The recorded fixtures are a
reference-derived oracle, so treat them like code.

## Files

- `app.sh` - the tiny CLI under refactor (`greet greet [NAME]...`)
- `unit-test.sh` - the project's existing unit test (exit 0 + mentions the name)
- `refactor.sh` - the scripted agent edit: drops a comma "for cleaner formatting"

Generated by the walkthrough (not committed): `tests/` and `fixtures/`.

## Walkthrough

Commands below use `npx smokepod`; a locally installed `smokepod` works the same.
Run everything from this directory (`examples/agent-refactor/`).

### 1. Meet the CLI and its tests

```bash
./app.sh greet world        # Hello, world!
./unit-test.sh              # unit tests pass: Hello, world!
```

### 2. Lock the baseline

```bash
npx smokepod init --target ./app.sh --probe "greet world"
```

`init` probes `--version`, `--help`, and your `--probe` commands, scaffolds
`tests/smoke.test`, records golden-master fixtures, and writes the protecting
manifest:

```
Wrote tests/smoke.test
Wrote fixtures/smoke.fixture.json
Wrote fixtures/manifest.json
```

The scaffolded sections cover `--version` (as a regex, so version bumps do not
trip it), `--help`, and the real `greet world` invocation:

```
## greet
$ "$SMOKEPOD_TARGET" greet world
Hello, world!
```

### 3. Confirm the gate is green

```bash
npx smokepod verify --target ./app.sh --tests tests --fixtures fixtures
```

```
...

RESULT: 3 passed (3 total)
```

### 4. The "bad refactor"

An agent (or a tired human) improves the code. It works, and the unit test
agrees:

```bash
./refactor.sh               # refactor applied
./unit-test.sh              # unit tests pass: Hello world
```

The unit test asserts the greeting mentions the name and exits 0. "Hello world"
does. Tests green, ship it?

### 5. The gate disagrees

```bash
npx smokepod verify --target ./app.sh --tests tests --fixtures fixtures
```

```
..

FAIL: greet / "$SMOKEPOD_TARGET" greet world
stdout:
--- expected
+++ actual
@@ -1 +1 @@
-Hello, world!
+Hello world
F

CHANGES (1):
  tests/smoke.test greet:1: Hello, world! -> Hello world

RESULT: 2 passed, 1 failed (3 total) [FAIL]
```

Named section, exact diff, exit 1. Maybe the comma was intended; maybe it breaks
someone's parsing. That is precisely the judgment call verify refuses to make
silently on your behalf.

### 6. Review and accept, or reject

Accept the change deliberately (the old-vs-new diff prints before anything is
written):

```bash
npx smokepod update --all --target ./app.sh --tests tests --fixtures fixtures --yes
```

```
--- recorded: fixtures/smoke.fixture.json
+++ re-recorded
## greet
$ "$SMOKEPOD_TARGET" greet world
- Hello, world!
+ Hello world

Update complete: 1 fixture(s) written, manifest refreshed
```

Without `--yes`, `update` prompts per file for interactive review. The `--all`
flag matters: `update` auto-detects baseline files edited on disk, but a changed
target needs `--all` to re-record from the live output.

Or reject it and the baseline is green again with no fuss:

```bash
git restore app.sh
npx smokepod verify --target ./app.sh --tests tests --fixtures fixtures
```

### 7. Reset

```bash
git restore app.sh
rm -rf tests fixtures
```

## What to take away

- Unit tests assert what someone thought to assert; the characterization
  baseline captures everything you recorded, exactly.
- The guardrail loop: `init` before refactoring, `verify` after every change,
  `update` only with a reviewed diff. Never re-record to make a failure
  disappear.
- See [docs/agent-integration.md](../../docs/agent-integration.md) for the
  guardrail skill, hook recipes, and an AGENTS.md contract that wire this
  loop into Claude Code and OpenCode.
